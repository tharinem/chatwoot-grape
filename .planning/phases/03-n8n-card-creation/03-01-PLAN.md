1. Create `kanban-api/src/lib/redis.ts` — IORedis connection for BullMQ (per D-11):
   - Export `redisConnection` as a config object (NOT an IORedis instance — per research pitfall 5, BullMQ should manage its own connections):
     ```typescript
     import type { ConnectionOptions } from 'bullmq';

     export const redisConnection: ConnectionOptions = {
       host: process.env.REDIS_HOST ?? 'localhost',
       port: parseInt(process.env.REDIS_PORT ?? '6379', 10),
       db: parseInt(process.env.BULLMQ_REDIS_DB ?? '2', 10),
       maxRetriesPerRequest: null,
       password: process.env.REDIS_PASSWORD || undefined,
     };
     ```
   - Export type only, no IORedis instance creation (BullMQ creates its own connections from this config).

2. Create `kanban-api/src/lib/api-key.ts` — API key generation, hashing, verification:
   - `generateApiKey()`: Returns `{ raw, prefix, hash, salt }`. Uses `crypto.randomBytes(32).toString('hex')` for 64-char raw key. Prefix = first 8 chars. Salt = `crypto.randomBytes(16).toString('hex')`. Hash = `crypto.createHash('sha256').update(salt + raw).digest('hex')`.
   - `hashApiKey(key: string, salt: string): string`: SHA-256 of salt+key.
   - `verifyApiKey(prisma: PrismaClient, rawKey: string): Promise<ApiKeyRecord | null>`: Extracts prefix (first 8 chars of rawKey), queries `prisma.apiKey.findFirst({ where: { prefix, revokedAt: null } })`, compares hash using `crypto.timingSafeEqual`. Returns the record if match, null otherwise.
   - Use `import crypto from 'node:crypto'` and `import type { PrismaClient } from '@prisma/client'`.

3. Create `kanban-api/src/services/api-key-seed.ts` — Auto-generate API key on first auth (per D-02, following stage-seed.ts pattern):
   - `seedApiKey(prisma: PrismaClient, accountId: number): Promise<string | null>`: Checks if account has any non-revoked API key. If yes, returns null. If no, calls `generateApiKey()`, creates record with `prisma.apiKey.create({ data: { accountId, keyHash: hash, salt, prefix } })`, returns the raw key string.
   - Import `generateApiKey` from `../lib/api-key.js`.

4. Create `kanban-api/src/schemas/webhook.ts` — Zod schemas for webhook (per D-06):
   - `webhookPayloadSchema`: z.object with `contact_name: z.string().min(1).max(255)`, `conversation_id: z.number().int().positive()` (required for webhook, unlike card creation), `channel_type: z.string().max(50).optional()`, `assignee_id: z.number().int().positive().optional()`, `phone: z.string().max(50).optional()`, `email: z.string().email().optional()`, `conversation_url: z.string().url().optional()`.
   - `webhookResponseSchema`: z.object with `status: z.string()`, `job_id: z.string()`.
   - Export both schemas and inferred types.

5. Create `kanban-api/src/schemas/api-key.ts` — Zod schemas for API key management:

   - `createApiKeyResponseSchema`: z.object with `id: z.string()`, `raw_key: z.string()`, `prefix: z.string()` — shown only at creation time.
   - Export both schemas.
